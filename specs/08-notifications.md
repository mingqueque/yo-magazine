# 알림

- 상태: 검토중
- 최종 갱신: 2026-08-21
- 원문: Notion `알림센터 (단순화가 더 필요한 것 같아 검토중입니다)`

원문 페이지 제목에 단순화 검토중 표시가 남아 있다. 알림센터 구조 확정 전까지 확정 기능처럼 디자인하거나 개발 범위에 넣지 않는다.

## OS 알림 권한

- 론칭 버전에는 앱 내 알림 설정을 개발하지 않고 OS 알림 권한을 따른다.
- 마이페이지의 알림 설정 메뉴는 OS 알림 권한 토글과 연동된다.

## 푸시 알림

푸시 알림을 클릭하면 알림센터로 이동한다. 푸시 알림에는 글과 댓글의 상세 내용이 노출되지 않도록 설계한다. 상세 내용은 알림센터에 들어가야 볼 수 있다.

### 즉시 알림 · 댓글

| 상황 | 문구 |
| --- | --- |
| 내 글에 댓글이 달린 경우 | 내 글에 댓글이 달렸어요 📮 |
| 에디터가 댓글을 단 경우 | 에디터가 댓글을 달았어요 📮 |

### 스케줄 알림 · 좋아요

하루 1회, 20:00~21:00 사이에 24시간 동안 발생한 좋아요를 모두 합쳐 알림 1개로 발송한다.

| 해당 시간대 좋아요 발생 | 푸시 알림 문구 |
| --- | --- |
| 게시글에만 발생 | 오늘 내 글에 좋아요 10개가 달렸어요 💗 |
| 댓글에만 발생 | 오늘 내 댓글에 좋아요 10개가 달렸어요 💗 |
| 게시글과 댓글 모두 발생 | 오늘 내 글과 댓글에 좋아요 10개가 달렸어요 💗 |

## 알림센터

### 닷 표시

- 발생 기준: 새 알림이나 푸시 알림이 발생하면 알림센터 버튼에 닷을 노출한다.
- 제거 기준: 알림센터 페이지 진입을 기준으로 닷을 제거한다.

### 적재 규칙

- 론칭 버전에 한하여 아이템별 읽음 표시는 제공하지 않는다.
- 푸시 알림의 좋아요는 하루 1회 몰아서 발송하지만, 알림센터에는 댓글과 좋아요 모두 즉시 쌓인다.
- 스케줄러를 통해 특정 시간에 보내는 푸시 알림도 알림센터에 적재한다.
- 푸시 알림과 알림센터의 알림 아이템 문구는 동일하지 않다.

### 알림 아이템 구성

범용이 가능하도록 요소별로 구성한다.

1. 내 글에 새 댓글이 달린 알림
   - 반응 종류 `댓글`
   - 글 제목 (최대 1줄)
   - 카테고리
   - 알림 발생 시간
   - 댓글 미리보기 (최대 1줄)
   - 에디터의 댓글은 댓글 내용 좌측에 `에디터`를 노출한다.
2. 내 글에 좋아요 알림
   - 반응 종류 `좋아요`
   - 글 제목 (최대 1줄)
   - 카테고리
   - 알림 발생 시간
   - 추가된 좋아요 수
   - 처음 받는 좋아요여도 `새로 달렸어요.`를 사용한다.
3. 내 댓글에 좋아요 알림
   - 반응 종류 `좋아요`
   - 카테고리
   - 내가 썼던 댓글 (최대 1줄)
   - 알림 발생 시간
   - 추가된 좋아요 수
   - 처음 받는 좋아요여도 `새로 달렸어요.`를 사용한다.

### 좋아요 알림 발생 규칙

- 동일 유저가 동일 콘텐츠에 좋아요 상태를 여러 번 설정하거나 취소할 수 있으나, 좋아요 알림 이벤트는 최초 좋아요 시 1회만 발생한다.
- 최초 좋아요 이후 취소하더라도 최초 좋아요 이력은 유지하며, 다시 좋아요를 눌러도 추가 알림을 생성하지 않는다.

### 본인 예외

본인 글이나 본인 댓글에 본인이 좋아요를 누른 경우, 그리고 본인 글에 본인이 댓글을 등록한 경우에는 알림을 발생시키지 않는다. 알림센터 적재와 푸시 알림 모두 발생하지 않는다.

## 슈퍼유저 관련

- 슈퍼유저가 일반 유저의 글이나 댓글에 좋아요를 누른 경우, 알림에 에디터의 좋아요라는 사실을 알리지 않는다. 구현 가능 여부는 [10-open-decisions.md](./10-open-decisions.md)에서 관리한다.
- 슈퍼유저가 일반 유저 글에 댓글을 단 경우에는 에디터의 댓글이라는 알림을 제공한다.
